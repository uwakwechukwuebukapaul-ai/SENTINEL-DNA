## Architecture changes

The release preserves the existing architecture. The certified release
boundary contains the controlled deployment adapter, immutable release
metadata, deterministic release manifest, protected production configuration,
the internal Nginx boundary, and isolated SQLite backup/restore services.

The scoped certification change is in `scripts/release_gate_diagnostics.py`:

- GitHub Actions resources remain resolved through the authoritative numeric
  repository ID.
- The target SHA is matched exactly before workflow selection.
- Duplicate push-triggered runs are selected deterministically by newest
  Actions database ID.
- Selected runs must be completed and successful, use the expected event, and
  when a branch is explicitly configured match it; they also carry the
  expected repository ID, repository name, head repository ID, and head
  commit SHA.
- The JSON result now includes explicit commit-custody evidence.

No production API, database, deployment, or authentication contract was
changed by this fix.

## Security controls

The release retains fail-closed behavior for invalid release metadata,
unexpected manifest fields, mutable or untrusted configuration, public
internal service ports, unverified image identity, unsafe ACLs, and restore
targets that could overwrite backup inputs. Secrets are excluded from release
metadata and diagnostic error output. CI evidence remains separate from
deployment authorization, image custody, and GHCR publication.
